# Deploy FINN backend on Render (free) and run the protected host check

Nothing here has been deployed or run on Render yet. Everything below is the plan plus tested-with-mocks code.

## 1. What you do (I cannot create accounts or enter keys for you)
1. Put the folder in a **private** GitHub repo. `.env` is git-ignored; do not commit it. Run `git status` and confirm no `.env`, `.venv`, `data/pdfs`, `results/` are staged.
2. Groq: create a key at console.groq.com (check whether the model `qwen/qwen3.8-27b` is listed for your account, and whether a card is needed).
3. Render: New > Blueprint > pick the repo. It reads `render.yaml`.
4. Render asks only for the values marked `sync: false`. Enter them in the Render dashboard, not in chat.

## 2. Environment variables (exact)

| Name | Value | Secret? | Notes |
|---|---|---|---|
| FINN_LLM_API_KEY | your Groq key | **yes** | Dashboard prompt (sync: false). Never in git. |
| FINN_ADMIN_TOKEN | auto-generated by Render | **yes** | Copy it from Dashboard > Environment. Needed for the host check. |
| FINN_ENABLE_HOST_CHECK | 1 | no | **Set to 1 only while testing. Delete the variable (or set 0) afterwards**; the admin routes then return 404. |

| FINN_LLM_EXTRA_BODY | {"reasoning_effort":"none"} | no | in render.yaml; if Groq rejects it, delete this variable and retry |
| FINN_LLM_TIMEOUT_S | 30 | no | |
| FINN_LLM_MAX_RETRIES | 1 | no | |
| FINN_LLM_MAX_TOKENS | 700 | no | |
| FINN_LIVE_MAX_PER_MIN | 2 | no | live-call budget (in-memory) |

`.python-version` pins Python 3.13. If the build fails on a package, tell me the exact error.

## 3. Run the host check (from your Mac Terminal)
Copy the token from Render yourself. Do not paste it into chat or into a file in the repo.

```bash
cd "/Users/nikhil/enam assg"
mkdir -p results
read -rs FINN_TOKEN
# paste the token, press Enter (nothing is shown)
export FINN_TOKEN
URL="https://YOUR-SERVICE.onrender.com"

curl -s "$URL/healthz"
# first request after idle can take ~1 min (free instance cold start)

curl -s -X POST -H "Authorization: Bearer $FINN_TOKEN" "$URL/admin/host-check?model=1"
# prints {"job_id":"...","poll":"..."}

curl -s -H "Authorization: Bearer $FINN_TOKEN" "$URL/admin/host-check/JOB_ID" -o results/render_host_check.json
# repeat until the file shows "status": "done" (about 1-4 minutes)
unset FINN_TOKEN
```
Then tell me the file is saved. I will read it and do the claim-by-claim check against the PDF text.

`model=0` skips the Groq requests (use it first if you want to test network access only).

## 4. After testing
- Remove FINN_ENABLE_HOST_CHECK (admin routes become 404).
- Rotate the Groq key if you pasted it anywhere by mistake.
- To make a verified live answer the cached demo answer: `python scripts/promote_to_snapshot.py results/render_host_check.json Q1_concall_guidance "Your Name"`, commit, push.

## 5. Safety design of the host check
- Off unless FINN_ENABLE_HOST_CHECK=1 **and** a token exists; otherwise 404 (route not advertised).
- Bearer token in the Authorization header only (query-string tokens are rejected), constant-time compare.
- 5 wrong tries in 10 minutes locks the endpoint for everyone (429).
- Fixed targets only (no URL parameter, so it cannot be used as a proxy); one job at a time; at most one start per minute.
- Output contains no env vars or keys (key shown only as "set"/"missing"); errors are scrubbed.
- The public `/api/research` accepts only predefined question IDs, so visitors cannot spend your Groq quota on arbitrary prompts. Live calls are capped by the budget variables.
- Still true: anyone with the token can trigger outbound requests to those fixed sites and one or two Groq calls. Treat the token as a password and disable the route afterwards.

## 6. Cached answers survive restarts
Render's free disk is wiped on restart and redeploy. The extracted text and cached answers are committed in `data/snapshot/` and ship with every deploy; the app never writes at runtime. `/api/research` labels cached results (`CACHED demo result | ... | generated <date>`) and says "operator-written extract, NOT model output" until a real model answer is promoted.
Limits: free instances sleep after ~15 min idle (cold start about a minute); Render's own limits (free instance hours, build minutes) apply, check your dashboard.
