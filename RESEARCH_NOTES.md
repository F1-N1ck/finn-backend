# Generic research flow: status

**Claim status: NOT yet shown to generalise.** Everything below was tested offline (fake network, fake model,
real KPIT PDFs). Nothing has run against the live Screener/BSE/Groq path for a ticker other than KPITTECH's earlier
fixed-question tests. Do not describe this as generalising until `scripts/run_research_tests.py` passes on Render
for an unfamiliar ticker and the claims are checked by hand.

## Flow
ticker check -> Screener company page (name, NSE/BSE code) -> latest annual report + latest earnings-call transcript
with a link -> guarded download -> PDF text with PDF page numbers -> three model calls (overview, outlook, numbers)
-> mechanical checks -> brief with citations. Job based: `POST /api/analyze {ticker}` then `GET /api/analyze/{job_id}`.

## Protections
- Ticker: ASCII `[A-Z0-9&-]`, max 20 chars; unknown body fields (e.g. `url`) rejected with 422.
- Hosts: exact allowlist (www.screener.in, www.bseindia.com, nsearchives/archives.nseindia.com); https, port 443 only;
  redirects re-checked; host must resolve to public IPs only. Links on other hosts (e.g. company sites) are reported
  as `host_not_trusted`, never fetched.
- Caps: 35 MB download, 75 s per download, 80 s extraction, 270 s per job, 600 pages; PDFs must start with `%PDF-`.
- Limits: one analysis at a time; 8 live analyses/hour and 20/day (global); cached briefs cost no budget;
  model calls paced to ~6,500 tokens/min (Groq key limit is 8,000).

## States reported
ticker_not_found, source_unreachable, company_not_resolved, ticker_mismatch, documents_not_listed; per document:
host_not_trusted, not_found, inaccessible_http, timeout, too_large, not_pdf, malformed_pdf, encrypted,
scanned_no_text (no OCR), too_slow, partial (page/time cap). Sections: found / not found / unverified / unavailable.

## Known limits (unverified or by design)
- Screener's raw HTML was never seen; the parser was built from a text summary plus a defensive fallback. Tested only
  on a reconstructed fixture. First real run may need a parser fix (the job error includes diagnostics).
- Many transcripts/ARs are on company sites or listed without a link: those give "not found", not a guess.
- Speaker roles are detected from a "MANAGEMENT ... MR. X - title" block (KPIT format). Other formats fall back to
  plain windows with a stricter prompt and a visible warning; outlook quality there is unmeasured.
- Number extraction relies on a page that looks like an income statement; companies with unusual labels may get
  "not found". Scope/unit/period must appear in the cited passage; PDF fonts can turn the rupee sign into a backtick.
- Mechanical checks do not verify meaning. Page numbers are PDF indexes (KPIT AR spreads differ from printed pages).
- Disk cache lives in /tmp and is lost on restart; free instance spins down after ~15 min idle.
- NSE announcement/attachment endpoints were slow or timing out from Render, so exchange discovery is not used.

## Reliability changes (2026-11-01, second round)
- Job hard limit (FINN_JOB_HARD_LIMIT_S, default 420 s): a stuck job becomes `failed / job_timeout`; the slot is freed.
- Pipeline deadline (FINN_RESEARCH_DEADLINE_S, default 270 s): fetch/extract/model steps get what is left; steps skipped for time are reported, not hidden.
- Model-wait cap: the token pacer waits at most 70 s per call, then the section is marked unavailable.
- `outcome` on every job/brief: complete | partial | no_findings | snapshot_fallback | failed. The page shows a PARTIAL banner.
- Every poll response carries `instance`; an unknown job returns 404 with a note that the free server may have restarted.
- A rupee sign drawn with a font whose code is "H" or backtick is read as the rupee sign (HUL, KPIT). Pidilite's glyph is absent from the PDF text layer, so per-share items there fail the unit check (correct).
- Citation pages come from the quote's position inside the passage (`page_basis: located_in_passage`).
- scripts/run_research_tests.py saves after every poll and company; unexpected polls are saved with HTTP status and a redacted body.
- (round 3) Transcripts older than 15 months are not used as outlook (COFORGE's only accessible call was Feb 2022). One patient retry on model rate limits (waits the provider's retry-after if it fits the time budget); sections now carry `provider_detail` and `retry_after_s` when the model call fails.
- (round 4) A transient download failure (timeout, 5xx, connection error) on the newest document is retried once with a longer first-byte wait before an older document is used; if an older call is used, the outlook section says so. The date printed in a transcript is compared with Screener's month label (`date_matches_label`). Per-share items display as `64.01 ₹ per share` (no doubled sign). The test script flags stalls of its own loop (`client_pause_s`, `active_wall_s`).
- (round 5) Retrieval rules, all general: PDF ligatures (ﬁ, ﬂ) are spelled out at extraction so 'Proﬁt' matches 'profit'; an income statement is recognised by its line items (revenue from operations, total income, tax expense, profit lines, earnings per share), not only by a heading, and the passage starts at the statement when it sits below a balance sheet on a long page; the business overview prefers 'About ...' / 'Company overview' / 'Who we are' pages and the 'Corporate information' accounting note, and discounts CSR/ESG pages and director/address directories. Known gap: for some reports (HUL) the real description page is not ranked first.
- (round 6) Found while checking the saved TATAELXSI and ASTRAL briefs against their PDFs. (a) A listed "transcript" can be a one-page cover letter that links an audio recording (ASTRAL, Feb 2026). A document is now accepted as a transcript only if it has at least 8,000 characters and speaker turns or a "Moderator" line; otherwise it is skipped with state `not_a_transcript` and the section says so instead of showing the document as "ok". (b) The call date was read from the covering letter (the filing date), so Tata, HUL and Pidilite briefs said "call dated" with a later date. It is now read from the call's own title page (`find_call_date`); a letter with no call page gives no date. A Screener label within one month of the printed date counts as matching. (c) Rupee-font replacement only runs on pages with a rupee-like glyph ("H" or backtick before a number or unit), so ordinary pages use plain text and heavy pages cost less CPU. Not fixed: poll stalls of ~45 s seen on Tata (suspected CPU contention during extraction, unproven), and `warm_up_bse` can add up to ~20 s.
- (round 7) **No generated summaries.** The model is no longer asked for a "summary" and the brief has none; every sentence shown is a claim with its own quote and citation. A claim that names a fiscal period (FY27, Q2, H2; "2H" = "H2") is rejected unless the quoted words name that period too, because a period can otherwise be guessed from elsewhere in the passage (Tata Elxsi's call text contains "H2FY26" as the prior-year base, the call itself is Q2 FY27). Rejected claims are listed with the reason.
- (round 7) **Company-hosted transcripts** (`finn/research/hosts.py`). Only transcripts, never annual reports. A host other than the exchange archives is accepted only if (1) it is the company website listed on its Screener page or a subdomain of it, or (2) it is on another domain that the listed website's home page links to AND whose name part agrees with the company name (Astral lists astralpipes.com but files transcripts on astralltd.com). Shared platforms (CDNs, cloud storage, link shorteners, social sites) never qualify; Tata Elxsi's April 2026 transcript on a cloudfront.net address is refused. Every hop of a download is re-checked: https only, port 443, host inside the approved domain, all resolved addresses public, and the socket is opened to an address checked at connect time (certificate still verified against the host name). Company-hosted files are capped at 15 MB and 45 s (exchange files: 35 MB, 75 s), must start with %PDF-, then pass the same transcript test (>= 8,000 characters and speaker turns) and call-date test. The brief shows the source host, why it was accepted, the call date, and for each file that was not used: host, state, HTTP status, size/pages.
- (round 7) Not verified by anyone but the app: the Screener "website" link is Screener's data, not an independent registry. The check protects against links to unrelated hosts, not against a wrong website listed by Screener or a compromised company site. If a proxy is configured in the environment, requests go through it and connect-time pinning does not apply (Render does not set one).
- (round 7) Speaker roles: a title that wraps onto the next line ("EXECUTIVE / DIRECTOR & CHIEF FINANCIAL / OFFICER") made Astral's CFO an "analyst", so his guidance was never shown to the model; a speaker list that continues on page 2 was also cut. Both fixed.
- (round 7) **Poll delay evidence** (finn/research/timing.py). In the 3 Tata Elxsi runs a poll took 10-46 s while the job was healthy. Only the latest run's raw data survives (results/ is git-ignored and overwritten), and it shows: poll 4 took 10.97 s and the server's own elapsed_s in that reply was 33.9 s for a request sent at 23.5 s, so the handler ran about 10 s after the request was sent; this was when the annual-report download/extract stage started. Poll 11 took 45.95 s; the client had no pause; the reply says the job finished at 73.8 s. Cause not established. The server now records: oversleep of a probe thread and of a probe task on the event loop, with the CPU time used during it; X-Received-At / X-Responded-At on each poll; the running stage. The test script saves them per poll with a before-app / handler / after-handler split. Render's own logs have not been read.
- (round 8) **Statement passage keeps its title.** On Coforge's annual report the income statement sits under the balance sheet on one PDF page; the passage started 500 characters above "Revenue from operations", which was after the title "Consolidated Statement of Profit and Loss (All amounts in INR Mn ...)". The model then saw no scope and no unit, answered unit "not stated", and the scope check (correctly) rejected all three items, so the section was "unverified". The passage now starts at the statement's own title line when one is within 3,000 characters above the table; otherwise the old rule applies. No check was changed; a page with the title removed still fails `scope_not_in_passage` and `unit_not_in_passage` (tested). Whether the model now passes is only known after a live run.
- (round 8) **Output-token budget.** The saved Tata Elxsi 429 names the limit in the provider's words: "on output tokens per minute (OTPM): Limit 1000, Used 625, Requested 600" (retry in 13.5 s). The pacer only budgeted total tokens (7000/min), so it could not prevent this: the three calls request 600 + 500 + 600 output tokens. `TokenPacer` now also keeps an output budget (`FINN_LLM_OTPM`, default 1000; 0 = off) using the requested max_tokens before a call and the real completion_tokens after it. Expect a longer job when the key really has this limit (roughly two extra waits of up to a minute). Not established: whether that limit is per key, per organisation or per model, or whether it will stay 1000. `rate_limit` {code, name, limit, used, requested} is saved on a failed section, parsed only from the provider's text; organisation ids are masked in `provider_detail`.
- (round 8) **Poll delay, what the saved data shows** (research_tests.json, 3 runs, 2026-11-03). (1) In all three runs the LAST poll took 45.53 / 45.58 / 45.56 s; the app stamped the request 45.5 s after the client sent it and answered in 0.00 s. Other polls: 0.5-1.1 s. The client opens a new connection for every poll (`requests.get`), so it is not a stale keep-alive connection. (2) The event-loop and thread probes recorded no stall in that window, so the process was responsive. So the wait happened before the request reached the app (edge/proxy, network or client); cause NOT established. A fixed 45.5 s is timer-like, not load-like. (3) A different delay: Tata poll 2 had the handler itself take 15.8 s (event loop lag 9.0 s and 5.7 s, thread lag 8.9 s with only 1.4 s CPU used) during annual-report extraction (27.8 s wall; CPU about 3.5 s). Slow extractions (Astral first call 20.9 s for 29 pages, Tata AR 27.8 s for 152 pages) used little CPU; fast ones (Astral AR 247 pages in 5.0 s) were CPU-bound. That points to waiting, not computing; CPU throttling, steal, cold disk reads or memory pressure are all still guesses. New data to settle it: per-stage `cpu_s`, `host_cpu` (cgroup throttling, CPU pressure, steal) in each poll, and a `/healthz` ping every 3 s during each run (`pings` in the saved run), which shows whether the whole instance or only the poll request stalls.
